# 营销一体化 V6 并行开发版本（2026-11-14）

本目录（`workbench-v6/`）是营销一体化工作台的 **V6 并行开发版本**，以独立子目录加入本仓库，供与仓库根目录的原版原型**比较与讨论**，**不替换原版**。两版可在同一本地端口并排打开（见下文）。

V6 为纯前端离线原型：统一财务自然月口径、同页九组指标分析、80/20 变化用户排序、18 章精简月报与多格式导出、唯一手填全局补充。全部数据为合成样例或明确标注的原型模拟数据，无后端、无生产数据。

## 如何查看

无需安装、无需构建、无网络依赖（无 CDN、无外部 http 资源、无真实账号登录）。

1. **直接打开**：下载本共享分支的 ZIP 并解压，双击 `workbench-v6/index.html`（`file://` 协议即可完整运行）。
2. **本地服务并排比较**：在仓库根目录执行 `python3 -m http.server 8000`，然后访问：
   - V6：<http://localhost:8000/workbench-v6/>
   - 原版（仓库根目录原型）：<http://localhost:8000/>

整个目录可原样拷贝到离线电脑使用。图表库为本地 `echarts.min.js`（ECharts 5.5.0，文件内保留原 Apache-2.0 许可证声明）。

首次打开默认身份为「部管理员 · 李澈」（覆盖全部 2,000 张表卡），仅作演示入口；查看其他范围请从顶栏头像切换身份。

## 核心能力概览

- **自然月统一口径**：全局默认「财务自然月」，首页、分析、报表、地图同源；新增/注销按用户立户/注销日期的自然月归属派生，不改源事实。
- **同页九组指标分析**：售水量、注册用户、产销差率、单价、收费率、表务、预警、工程未立户、应收账款九组在同一分析页可达，沿真实组织树不等深下钻；可开启第二完整外框（独立指标组＋维度，共享组织/期间）做对比，双框全宽纵向堆叠。原五组业务工具经遗留抽屉保留可达。
- **共同条件即时生效**：统计时段、月份及展开后的筛选条件变更后自动应用并刷新下方分析框；「查询」保留为手动刷新，「重置」恢复默认条件后立即刷新。切换经营单位先清空原组织节点；开始月份晚于截至月份时提示错误、不提交无效条件。
- **组合图与窄屏自适应**：图表按指标含义组合——绝对量柱＋占比环、重点用户户数/水量双环、供售水量＋产销差率双轴；宽度 <880px 自动退化为单轴图。图表随容器实际尺寸（窗口缩放、导航收展、双框切换）重新布局。
- **18 章精简月报**：保留 18 个原大标题与顺序，图表优先＋逐块简短摘要；仅第十五章（各用水性质售水量对单价影响）与第十八章（牟新水务营销指标）在有数据时保留必需汇总表；逐户明细台账不入月报导出（应用内分析覆盖与明细导出不变）。导出格式：HTML 离线快照、ZIP（分章汇总 CSV＋PNG＋manifest.csv＋缺数说明.txt），分析框另支持 CSV/PNG。导出按当前身份/范围/期间生成并附数据性质标识；导出过程中身份、范围、查询条件或手填版本任一变更即中止。
- **节点自身名称筛选**：分析页组织「切换节点」提供搜索框与清空按钮，按节点自身名称（不含父级路径）即时筛选本轮授权候选；无匹配时禁用下拉并提示，清空即恢复完整列表与原当前节点。筛选只作用于候选列表，不改查询条件与全局状态。
- **变化对象 → 档案统一浮层**：全部弹窗与抽屉共用统一浮层宿主，同层按打开顺序叠放；在明细弹窗内打开用户档案抽屉不再被遮挡，关闭抽屉即回到原弹窗继续操作。
- **80/20 变化用户排序**：按变化绝对值升/降排序，N 为本期与基期均有结算的可比用户（含 0 变化，缺基期单列不计 0）；K 取「达到该方向 80% 变化量所需户数」与「20%×N 向上取整」的较小值，实际覆盖可不足 80% 并明示 20% 上限。Top10/50 仅屏幕显示，入选全集与完整明细单独导出。
- **新增/注销同批水量**：新增按立户自然月分批，取该批在所选期间的水量；注销以同批上年全年水量（该年 12 个月结算齐备才给出）与注销当年已知完整月水量为参考对比；截至注销日的水量/变化量/变化率置空，不编造月内拆分、不年化。
- **唯一手填全局补充**：供水量与未注册用户数按绑定单位整体填报；集团汇总仅在四单位×全部月份完整时成立，下级不分摊、缺月不按 0、不推算局部产销差率。

## 数据与身份（均为演示）

- **组织与授权**：247 条授权树节点（集团 1＋单位 4＋营业所 5＋班组 22＋网格 13＋线路 202），高新 3 条候选对象单列、不入树。
- **身份**：8 类业务角色、12 个演示身份，按角色分组切换，责任范围可绑定到单位/所/班组/线路。**角色权限与手填授权均为前端演示逻辑，不代表生产权限体系，不产生正式授权。**
- **样例数据**：2,000 张表卡（营业 995／高新 500／东区 400／港区 105）、46 个账期（2023-01…2026-10）、92,000 条月度事实，全部为合成样例；源数据只读冻结，页面不写源、不回写账号。
- **原型模拟数据**：21 项原「源缺空态」需求由 `assets/prototype-data-v6.js` 提供确定性模拟样本，统一标注「原型模拟数据（非真实接入）」，只读冻结、不修改任何源数组；含 3 条只读预置自动工单样例（AUTO），非实时规则引擎、无真实自动执行。
- **范围与缺数规则**：查询只能缩小不能放大，越界深链渲染拒绝页；`—` 表示不适用/不可计算，`0` 表示确为零，权限不足单独提示，不以 0 冒充无权限。
- **牟新水务**：空占位单位，未接入数据，不参与统计/分母/排名，不造数。

## 边界与未实施

- 纯前端离线演示：不接中台、不建表、不创建真实账号、不做 SSO；没有数据库与后端服务，本期不连接任何生产数据。
- 所有写动作（手填、账号、规则、参数、计划值等）**仅保存在页面内存**，不写 localStorage、不落文件，**刷新即恢复**。
- 合成样例与原型模拟数据不代表真实业务阈值或生产口径；演示数值不向月报数字校准；排序仅呈现事实，不自动生成原因。
- 分区计量最终逻辑/总表本期暂不考虑（入口保留）；真实自动规则服务与考核未实施。

4. **月报与导出**：18 章图表优先精简月报及 HTML/ZIP/CSV/PNG 导出链路。
5. **口径与排序**：财务自然月统一口径、80/20 变化用户排序与新增/注销同批水量参考。

## 评审操作路径（建议）

1. 打开 `index.html`，从顶栏头像切换不同角色身份，观察首页与分析页的范围变化。
2. 进入分析页：选择指标组 → 沿组织树下钻 → 修改统计时段/月份，观察分析框即时刷新。
3. 在「切换节点」搜索框输入节点名称，查看候选筛选与清空恢复。
4. 开启第二外框，选择不同指标组/维度做对比；缩放窗口宽度，观察组合图与窄屏单图切换。
5. 打开月报并导出 HTML/ZIP；在分析框导出 CSV/PNG；导出中途切换身份可观察中止行为。
6. 从变化用户排序进入明细，在明细弹窗内打开用户档案抽屉，查看浮层层叠与关闭返回。

以上为建议查看路径。本 README 为交付说明，不构成验收、测试通过或上线结论。

## 文件结构

- 入口：`index.html`；本地图表库：`echarts.min.js`（ECharts 5.5.0）；样式与脚本：`assets/`，全部本地加载。
- V6 核心脚本：`assets/analysis-v6.js`（指标计算/排序/月报模型，`WBAnalysis`）、`assets/analysis-ui-v6.js`（分析渲染，`WBAnalysisUI`）、`assets/report-v6.js`（月报 HTML/ZIP，`WBReportV6`）、`assets/manual-v6.js`（手填全局，`WBSupplement`）、`assets/prototype-data-v6.js`（原型模拟数据，`WBPrototypeData`）。
- 继承脚本：`assets/data.js`、`assets/organization.js`、`assets/demo-profiles.js`、`assets/access.js`、`assets/engine.js`、`assets/shell.js`、`assets/home.js`、`assets/business.js`、`assets/admin.js`、`assets/views.js`、`assets/map.js` 等，与样式文件一并本地加载。
